01 / System Architecture

全景分层架构与模块交互关系

采用按实例隔离、带一次性 HMAC 令牌鉴权的 stdio JSON-line 管道连接 Java 逆向工作台与 Python 深度分析内核，彻底消除多实例端口冲突、C 扩展标准输出污染与 PIE 基址错位问题（右上角 ⋯ 支持一键复制高清图或导出 PNG / PDF）。

VulnHunter4Ghidra 双引擎混合系统架构图

Ghidra High P-Code SSA (Java 端) ⇄ 鉴权隔离 stdio JSON-Line 管道 ⇄ angr VEX + 状态机 + Z3 SMT (Python 端)

Ghidra 原生工作台层 (Java 21)

  • • ProgramScanner 在可取消后台 Task 中提取函数签名、Thunk 跳板及 -O2 尾调用跳转点。
  • • PCodeTaintAnalyzer 直接在反编译器 HighFunction SSA 图上追踪 Varnode Def-Use 与 Phi 节点，无需 Python 环境即可独立工作。
  • • VulnHunterProvider 与 TaintPathHighlighter 实现表格筛选、路径三色高亮及 .gpr 书签持久化。

隔离通信管道与双引擎融合器

  • • EngineManager 为每个 Ghidra 实例拉起专属 --stdio 子进程并注入 128-bit 随机令牌，告别固定端口抢占。
  • • 底层执行 fd 1 → stderr 描述符重映射，防止 VEX/Unicorn/Z3 原生库输出破坏 JSON-line 协议帧。
  • • Hybrid 融合器 对 SSA 与 VEX 独立命中的同源漏洞自动标记 [HYBRID] 并升级为最高置信度。

VEX 数据流 + 状态机 + Z3 核心

  • • taint.py 统一追踪寄存器与 sp/bp 栈帧槽位，建模 snprintf/atoi/strdup 传播并剔除 .rodata 常量误报。
  • • detectors.py 驱动有状态指针与算术状态机，精准捕获 CWE-415/416/476/190 与定长栈越界。
  • • verifier.py 与 sarif.py 执行有界 Z3 可行性剪枝，输出带 codeFlows 的标准 SARIF 2.1.0 报告。
02 / Core Highlights

六大核心技术亮点

针对传统二进制扫描工具“纯 CFG 可达性误报爆炸、PIE 地址错位、-O2 优化失明、存量告警无法落地门禁”四大痛点逐一攻克。

HYBRID IR SSA ∩ VEX 交叉印证

双引擎混合融合与零依赖离线降级

同时兼具 Ghidra 反编译器类型恢复与结构体感知优势（High P-Code SSA）以及 angr 跨函数符号求解优势（VEX + Z3）。分析无本地文件的远程 .gpr 或冷门单片机裸固件时可一键切换或自动降级至纯 Java P-Code 模式。

DATA-FLOW 常量与边界感知

统一栈帧坐标系与真实数据流污点传播

在 VEX 层打通 rsp 与 rbp 栈帧偏移，自动推断相邻栈槽容量上限，完整追踪 snprintf/atoi/strdup 等传播链，并自动过滤 printf("const %s", x)、system("const") 等只读常量参数假阳性。

LIFECYCLE CWE-415 / 416 / 476 / 190

有状态指针生命周期与跨函数整数溢出检测

摒弃“见 free 就报 UAF”的粗糙规则：精准跟踪 Allocated → NullChecked / Freed → Deref / SecondFree 状态迁移，识别 p = NULL 置空与重新分配消解（正常释放零误报），并支持跨函数受污染整数算术溢出（CWE-190）检测。

-O2 READY Tail-Call 尾调用识别

抗 -O2 / -Os 生产级编译优化

真实发布版固件与动态库会将函数末尾的 puts(p)、二次 free(p) 或包装函数调用优化为无栈帧的 jmp/b 尾调用跳转。双端扫描器均将跨函数 Jumpout 纳入一等调用建模，确保高优化产物不漏检。

Z3 SMT 死分支自动剪枝

有界 Z3 符号路径可行性验证

自动对外部 PLT 及 Mach-O 导入桩挂载符号化摘要，通过有界步数与活跃状态预算的 SimulationManager 验证分支约束可满足性（点亮 verified: true），自动剪除逻辑互斥的死代码分支。

DEVSECOPS SARIF + Baseline 门禁

SARIF 2.1.0 与存量基线差分门禁

原生输出带完整数据流步进轨迹（codeFlows）与 CVSS 安全评分的 SARIF 2.1.0 报告，无缝接入 GitHub Security 与 DefectDojo；配合 --baseline 指纹比对，老项目接入 CI 时只拦截新增高危漏洞。

03 / Module Relations

五阶段数据流流水线与核心模块契约

从二进制加载到逆向工作台染色与 CI 阻断，各模块边界清晰、职责单一。

STAGE 01

基址对齐与归一化

同步 Ghidra imageBase 至 angr，解析 Mach-O/PLT 导入桩，剥离 _chk 与平台前缀并加载 .toml 规则。

STAGE 02

双端 IR 构建

Java 端反编译产出 HighFunction SSA 图；Python 端构建单次缓存复用的 CFGFast 与 VEX 基本块。

STAGE 03

污点与状态机推导

执行过程内/跨函数污点传播，并行演进指针生命周期与受污染整数算术状态机。

STAGE 04

Z3 验证与双核融合

利用 Z3 SMT 剔除不可达死路径，按统一键融合 SSA 与 VEX 告警并升级 [HYBRID] 置信度。

STAGE 05

交互溯源与门禁输出

驱动反编译器三色路径染色与书签持久化，或经 --baseline 差分后输出 SARIF 2.1.0 门禁码。

05 / Quick Start

60 秒快速上手

既可编译安装至 Ghidra 进行图形化深度审计，也可通过 CLI / Docker 一行命令接入构建流水线。

1. 安装 CLI 与构建 Ghidra 插件
# 安装 Python 分析引擎与 `vulnhunter` 命令
python3 -m venv .venv && source .venv/bin/activate
pip install -e .

# 构建 Ghidra 11.x 扩展包（产物位于 dist/*.zip）
export GHIDRA_INSTALL_DIR=/path/to/ghidra_11.x
gradle buildExtension -PGHIDRA_INSTALL_DIR=$GHIDRA_INSTALL_DIR
2. 导出 SARIF 2.1.0 与增量基线门禁
# 加载固件规则包 + Z3 验证并导出 SARIF 2.1.0
vulnhunter report ./firmware.elf \
  --rules rules/embedded_iot.toml --verify \
  --format sarif -o vulnhunter.sarif

# 存量基线差分：仅在新增 High/Critical 漏洞时阻断构建
vulnhunter report ./firmware.elf \
  --baseline baseline.sarif --fail-on high
